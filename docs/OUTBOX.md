# Очередь исходящих сообщений

У каждого пользователя своя очередь в `db/<messenger>/users/<user_id>/outbox/`.

| Имя файла | Действие |
| --- | --- |
| `seen`, `seen_<id>` | Отметить чат прочитанным. Содержимое файла пустое. |
| `typing` | Показать индикатор набора. Содержимое файла пустое. |
| `*.txt` | Отправить текст в UTF-8. |
| `message_<id>.json` | Отправить сообщение в универсальном формате. |

## Сообщение с кнопками

`text` содержит готовый текст сообщения. Необязательное поле `buttons` содержит ряды кнопок. Каждый вложенный массив — один ряд, а `text` внутри кнопки — её подпись. У кнопки `callback` поле `payload` задаёт строку, которую получит бот. У кнопки `link` поле `url` задаёт HTTPS-адрес, который откроется при нажатии. Суффикс `<id>` делает имя файла уникальным в очереди пользователя.

```json
{
  "text": "Выбери пакет кредитов",
  "buttons": [
    [
      {"type": "callback", "text": "1000 кредитов · 19 ₽", "payload": "buy:1000"},
      {"type": "callback", "text": "5000 кредитов · 79 ₽", "payload": "buy:5000"}
    ],
    [
      {"type": "link", "text": "Условия оплаты", "url": "https://example.org/terms"}
    ]
  ]
}
```

Команда `/buy` использует кнопки `callback` для выбора пакета. После создания платежа приходит отдельное сообщение с одной кнопкой `link` для оплаты. Адаптер мессенджера преобразует кнопки в формат своего API. В MAX это вложение `inline_keyboard`.

## Отправка в MAX

Меню пакетов сохраняется как `message_buy_<seq>.json`, ссылка на оплату — как `message_payment_<id>.json`. Отправщик читает оба файла как `message_*.json`.

Отправщик MAX обрабатывает по одному файлу в порядке `seen` → `typing` → `*.txt` → `message_*.json`. Успешно отправленные сообщения удаляются. При неверном формате или ошибке отправки сообщение перемещается в `outbox-failed/`. Если часть длинного текста уже доставлена, сохраняется остаток.
