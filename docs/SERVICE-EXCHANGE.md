# Файловый обмен между сервисами

Все пути ниже указаны относительно каталога пользователя `db/<messenger>/users/<user_id>/`. Для MAX это `db/max/users/<user_id>/`.

## Входящие сообщения — `inbox/`

`ms-max` сохраняет входящие сообщения, а `ms-openai` читает их из очереди.

| Имя файла | Содержимое |
| --- | --- |
| `<seq>.txt` | Текст сообщения в UTF-8. Для сообщения только с вложениями файл пустой. |
| `<seq>.<nn>.<ext>` | Изображение или аудио. `<nn>` — порядковый номер вложения, например `112.01.jpg`. |

`<seq>` берётся из `message.body.seq` в MAX. `ms-max` сохраняет вложения первыми, а `<seq>.txt` публикует последним. Появление текстового файла означает, что сообщение готово к обработке.

`ms-max` сохраняет JPEG, PNG, GIF, WebP, MP3, OGG, M4A и WAV в исходном виде. При неподдерживаемом MIME-типе приём завершается с ошибкой. Текстовый файл сообщения не публикуется, маркер обновлений не продвигается.

## Исходящие сообщения — `outbox/`

`ms-max` отправляет файлы из очереди в чат. `ms-openai` кладёт туда ответы, расшифровки и служебные сигналы, а `ms-yookassa` — ссылки на оплату и подтверждения.

| Имя файла | Действие |
| --- | --- |
| `seen`, `seen_<id>` | Отметить чат прочитанным. Содержимое файла пустое. |
| `typing` | Показать индикатор набора. Содержимое файла пустое. |
| `*.txt` | Отправить текст в UTF-8. |
| `message_<id>.json` | Отправить сообщение в универсальном формате. |

### Сообщение с кнопками

`text` содержит готовый текст сообщения. Необязательное поле `buttons` содержит ряды кнопок. Каждый вложенный массив — один ряд, а `text` внутри кнопки — её подпись. У кнопки `callback` поле `payload` задаёт строку, которую получит бот. У кнопки `link` поле `url` задаёт HTTPS-адрес, который откроется при нажатии. Суффикс `<id>` делает имя файла уникальным в очереди пользователя.

```json
{
  "text": "Выбери пакет кредитов",
  "buttons": [
    [
      {"type": "callback", "text": "1000 кредитов · 19 ₽", "payload": "buy:1000"},
      {"type": "callback", "text": "5000 кредитов · 79 ₽", "payload": "buy:5000"}
    ],
    [
      {"type": "link", "text": "Условия оплаты", "url": "https://example.org/terms"}
    ]
  ]
}
```

Команда `/buy` использует кнопки `callback` для выбора пакета. После создания платежа приходит отдельное сообщение с одной кнопкой `link` для оплаты. Адаптер мессенджера преобразует кнопки в формат своего API. В MAX это вложение `inline_keyboard`.

### Отправка в MAX

Меню пакетов сохраняется как `message_buy_<seq>.json`, ссылка на оплату — как `message_payment_<id>.json`. Отправщик читает оба файла как `message_*.json`.

Отправщик MAX обрабатывает по одному файлу в порядке `seen` → `typing` → `*.txt` → `message_*.json`. Успешно отправленные сообщения удаляются. При неверном формате или ошибке отправки сообщение перемещается в `outbox-failed/`. Если часть длинного текста уже доставлена, сохраняется остаток.

## Заказы на оплату — `payments/orders/`

После выбора пакета через `/buy` сервис `ms-max` создаёт `payments/orders/<credits>.json`. Например, заказ на 5000 кредитов хранится в `5000.json` и содержит `{"credits":5000}`. Повторный клик сохраняет существующий заказ, пока файл находится в очереди.

`ms-yookassa` определяет цену по своему каталогу пакетов и сохраняет в заказе `idempotence_key` для повторных попыток. После создания платежа он кладёт ссылку в `outbox/` и переносит запись платежа в `payments/processing/<payment_id>.json`. После проверки статуса запись попадает в `payments/completed/` или `payments/failed/`.

## Файлы баланса

Каждый файл содержит одно целое неотрицательное число.

| Имя файла | Кто обновляет | Значение |
| --- | --- | --- |
| `credits_received.txt` | `ms-max` задаёт стартовое значение, `ms-yookassa` увеличивает его после успешной оплаты | Всего получено кредитов. |
| `credits_spent.txt` | `ms-openai` увеличивает после обработки запроса | Всего израсходовано кредитов. |

Текущий баланс — `credits_received − credits_spent`. При чтении отсутствующий файл считается нулём.
